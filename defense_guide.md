## Демонстрация

[↑ Наверх](#навигация)

### Шаг 1 — Игры
- Показать таблицу (ID первый столбец — это правильно)
- **Добавить** → заполнить поля → Сохранить
- Выбрать строку → **Изменить** → поменять цену → Сохранить
- Выбрать строку → **Удалить** → подтвердить

> *«Каталог игр. У каждой — название, цена, количество на складе, жанр и разработчик»*

### Шаг 2 — Жанры и Разработчики
- Быстро показать данные, добавить одну запись

> *«Справочники. Игры к ним привязаны через внешние ключи в базе данных»*

### Шаг 3 — Покупатели
- Показать список, добавить нового покупателя

> *«Учёт клиентов — имя, контакты, дата регистрации»*

### Шаг 4 — Покупки
- Показать таблицу: ID, покупатель, игра, дата, сумма, статус

> *«Каждая покупка связывает покупателя с игрой. Видно когда куплено и на какую сумму»*

### Шаг 5 — Дашборд ⭐
- Показать 4 карточки: доход, покупки, покупатели, игры
- Показать **график по месяцам**
- Показать **круговую диаграмму по жанрам**
- Удалить запись → перейти на дашборд → данные обновились

> *«Дашборд перечитывает данные из базы при каждом открытии — всегда актуален»*

### Шаг 6 — Показать код (если попросят)
- `MainView.java` — вкладки и кнопки
- `GameService.java` — SQL-запросы
- `DashboardView.java` — круговая диаграмма через SVG

## Архитектура

[↑ Наверх](#навигация)

### Три уровня приложения

```
┌─────────────────────────────────┐
│  VIEW (Vaadin)                  │  ← что видит пользователь
│  MainView, DashboardView,       │
│  DialogManager'ы                │
├─────────────────────────────────┤
│  SERVICE (Spring + Java)        │  ← бизнес-логика, SQL
│  GameService, CustomerService.. │
├─────────────────────────────────┤
│  DATABASE (H2)                  │  ← данные
│  schema.sql → data.sql          │
└─────────────────────────────────┘
```

### Что происходит при запуске

```
1. Application.java          → Spring Boot стартует
        ↓
2. application.properties    → Spring читает настройки
        ↓
3. H2 создаёт базу           → "computer_games" в памяти
        ↓
4. schema.sql                → CREATE TABLE Game, Customer...
        ↓
5. data.sql                  → INSERT INTO (тестовые данные)
        ↓
6. Spring создаёт сервисы    → GameService, CustomerService...
        ↓
7. Vaadin открывает MainView → загружает данные через сервисы
        ↓
8. http://localhost:8080      → готово
```

### Что происходит при нажатии «Добавить»

```
Кнопка (Vaadin)
    ↓
GameDialogManager.openAddGameDialog()   → открыл окно
    ↓
Пользователь заполнил поля → нажал «Сохранить»
    ↓
gameService.createGame(game)            → вызвал сервис
    ↓
JDBC PreparedStatement:
"INSERT INTO Game VALUES (?, ?, ?, ...)"  → SQL в базу
    ↓
grid.setItems(games)                    → обновил таблицу
```

### Про базу данных

```
jdbc : h2 : mem : computer_games
 │     │     │        │
 │     │     │        └── имя базы — придумано, любое слово
 │     │     └── mem = в памяти (сбрасывается при выключении)
 │     └── тип базы — H2
 └── протокол подключения
```

Имя `computer_games` должно совпадать в двух местах:
- `application.properties` — Spring создаёт базу
- `*Service.java` — сервисы к ней подключаются

## Кто что делает

[↑ Наверх](#навигация)

### Application.java — запускает всё
```java
SpringApplication.run(Application.class, args);
// одна строка — и всё запустилось
```

### Модели (Game, Customer, Purchase...) — коробки для данных
Просто хранят поля. Никакой логики.
```
Game = { gameID, title, price, stockQuantity, genreID, developerID }
```

### *Service.java — общение с базой
Умеют делать 4 вещи для каждой сущности:
```
getGames()    → SELECT * FROM Game
createGame()  → INSERT INTO Game
updateGame()  → UPDATE Game SET ...
deleteGame()  → DELETE FROM Game WHERE GameID = ?
```
Подключаются к базе через:
```java
DriverManager.getConnection("jdbc:h2:mem:computer_games", "sa", "")
```

### MainView.java — главный экран
- Создаёт 6 вкладок
- При старте вызывает все сервисы и загружает данные в таблицы
- При переключении вкладки — перечитывает данные из базы

### *DialogManager.java — всплывающие окна
Каждый отвечает за свою сущность:
```
GameDialogManager    → окна для игр
CustomerDialogManager → окна для покупателей
...
```
Открывает форму, принимает данные, вызывает сервис, обновляет таблицу.

### DashboardView.java — аналитика
1. Получает все покупки, игры, жанры
2. Считает общую выручку (`сумма всех totalAmount`)
3. Группирует покупки по месяцам → строит горизонтальный график
4. Считает покупки по жанрам → строит круговую SVG-диаграмму

### FieldFilter.java — фильтр таблиц
```
Получает: список игр + функцию Game::getTitle
Собирает: уникальные названия для выпадашки
Умеет:    вернуть только игры с нужным названием
```
Использует **stream** — конвейер обработки списка:
```java
items.stream()
     .map(Game::getTitle)        // достать названия
     .filter(Objects::nonNull)   // убрать пустые
     .collect(Collectors.toSet()) // убрать дубли
```

### schema.sql — структура базы
```sql
CREATE TABLE Game (GameID, Title, Price, ...)  ← создаёт таблицу
CREATE TABLE Purchase (... FOREIGN KEY (GameID) REFERENCES Game(GameID) ON DELETE CASCADE)
```
`ON DELETE CASCADE` — удалил игру → автоматически удалились её покупки.

## Как всё связано

[↑ Наверх](#навигация)

### Java, Spring, Vaadin — в чём разница

```
Java        — язык. Все файлы написаны на нём.

Spring Boot — каркас. Запускает сервер, создаёт базу,
              управляет сервисами (@Service),
              связывает классы между собой (DI).

Vaadin      — библиотека для UI. Grid, Button, Dialog,
              ComboBox — это всё Vaadin, но пишется на Java.
```

### Аналогия
```
Java        = кирпичи
Spring Boot = фундамент и каркас здания
Vaadin      = мебель и отделка внутри
```

### Связь между таблицами в базе

```
Genre ──────┐
            ├──→ Game ──────┐
Developer ──┘               ├──→ Purchase
Customer ───────────────────┘
```

- `Game` знает свой жанр и разработчика (хранит их ID)
- `Purchase` знает своего покупателя и игру (хранит их ID)
- Удалил `Game` → каскадом удалились все `Purchase` с этой игрой

## Топ-10 вопросов

[↑ Наверх](#навигация)

### В1. Что делает программа?

Веб-приложение для управления магазином компьютерных игр. Ведёт каталог игр, учитывает покупателей и покупки, управляет жанрами и разработчиками, анализирует продажи через дашборд.

[↑ К вопросам](#топ-10-вопросов)

---

### В2. Какие технологии?

- **Java 17** — язык программирования
- **Spring Boot** — каркас, сервер, управление зависимостями
- **Vaadin** — веб-интерфейс на Java (без HTML/JS)
- **H2** — встроенная база данных в памяти
- **Maven** — сборка проекта

[↑ К вопросам](#топ-10-вопросов)

---

### В3. Почему H2?

H2 запускается внутри приложения — не нужен отдельный сервер. Поддерживает полный SQL. При необходимости переключить на PostgreSQL — изменить одну строку в `application.properties`.

[↑ К вопросам](#топ-10-вопросов)

---

### В4. Как связаны таблицы?

Через внешние ключи:
- `Game` → `Genre` и `Developer`
- `Purchase` → `Game` и `Customer`

При удалении игры — автоматически удаляются её покупки (`ON DELETE CASCADE`).

[↑ К вопросам](#топ-10-вопросов)

---

### В5. Что такое Spring Boot?

Фреймворк для Java-приложений. Берёт на себя: запуск сервера Tomcat, создание базы данных, управление объектами через DI-контейнер (сам создаёт сервисы и передаёт их в нужные классы).

[↑ К вопросам](#топ-10-вопросов)

---

### В6. Что такое Vaadin?

Java-фреймворк для веб-интерфейса. Пишешь на Java — получаешь веб-страницу в браузере. Без HTML и JavaScript. Используемые компоненты: `Grid`, `Button`, `Dialog`, `ComboBox`, `DatePicker`.

[↑ К вопросам](#топ-10-вопросов)

---

### В7. Как реализован CRUD?

Для каждой сущности — `*Service` класс с 4 методами (`get`, `create`, `update`, `delete`) через JDBC `PreparedStatement`. `*DialogManager` открывает форму и вызывает нужный метод сервиса.

[↑ К вопросам](#топ-10-вопросов)

---

### В8. Какова архитектура?

Трёхуровневая: View (Vaadin) → Service (логика + SQL) → Database (H2). Модели — POJO-классы без логики, только поля.

[↑ К вопросам](#топ-10-вопросов)

---

### В9. Как работает дашборд?

При каждом открытии вкладки — заново загружает данные из базы. Считает выручку, группирует по месяцам и жанрам. Круговая диаграмма — чистый SVG, без сторонних библиотек.

[↑ К вопросам](#топ-10-вопросов)

---

### В10. Что такое `jdbc:h2:mem:computer_games`?

Адрес базы данных. `jdbc` — протокол, `h2` — тип базы, `mem` — в памяти, `computer_games` — придуманное имя. Spring создаёт базу с этим именем, сервисы к ней подключаются по тому же имени.

[↑ К вопросам](#топ-10-вопросов)
